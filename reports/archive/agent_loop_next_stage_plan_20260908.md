## 1. 总目标与当前起点

目标：用户提供问题、模型、明确预算，可选指定一个父 skill；框架自行生成算法代码、独立执行评测、把真实结果用于下一轮修订，维护最佳合法版本，导出可重载算法，并可靠停止。

这里的进化对象是算法代码，不是模型参数。完成不要求超过基线、历史 Island 或官方 EoH，也不要求每一轮改善。

当前已经建立的能力不重做：

- CVRP 构造接口 `select_next_node`，固定三个开发实例。
- i1/e1/m1 生成、改进、修复，真实分数与错误回传。
- incumbent、最近候选、EDIT TARGET 的明确区分。
- 逐实例反馈、简单停滞规则、固定上下文窗口。
- 主 loop 的请求子进程截止、认证分类、用量记录。
- 最佳生成版导出、显式父本重评续跑、journal 和运行报告。
- go5 记录证明三轮真实生成及反馈；go6_from_g2 记录已有显式父本十轮续跑。不要为了重复展示这两项能力再发起相同 live 运行。

现存边界：这些运行产物并不覆盖所有故障分支，也不能证明通用算法效果。最新 EoH 适配层的执行治理尚未达到主 loop 的保障水平，技能覆盖发布也仍有删除旧目录的空窗。

## 2. 总体设计原则

将问题定义、搜索策略、执行治理、算法资产分开，保留一个简单默认 loop，不另建科研总控制器。

- 问题定义负责数据、接口、可行性、目标、基线和套件身份。
- 搜索策略负责父本选择、修改对象、生成/修复/探索决策及接受规则。
- 执行治理负责真实请求和进程、预算、异常、取消、成本。
- 算法资产负责源码身份、评测证据、版本、导出和显式续跑。
- journal/报告记录事实，不回调模型，不成为检索记忆。

官方 EoH 是当前生产搜索入口：复用问题评测、外层预算与技能格式，保持上游算子含义，并在适配层记录执行治理限制和官方提交身份。

## 3. 实施批次 A：先补齐执行治理和发布可靠性

优先级：P0。先完成这批，再增加新的 live 运行或算法空间。

### A1. 统一实际请求预算

- 主 loop 与 EoH bridge 使用共用的有界请求能力。
- 每次外部 HTTP 请求发出前预留额度，初始化检查、网络重试、解析重试和重复候选重采样都不能绕过计数。
- 分开记录候选次数、逻辑生成次数、真实 HTTP 次数和 solver 调用次数；sample 数不是请求数。
- 主 loop 默认仍为零网络重试。EoH 上游内置重试必须受外层真实请求预算控制，并在配置和报告中明确。
- 请求总截止、全局墙钟截止和清理时间边界都明确；到期不再生成或评测。
- 已观察到的认证失败保留 provider_failed；取消后未知 token/费用为 null，不能记为零或假定服务端已停止计费。
- 未启动、预算前拒绝、已发送但结果未知、已收到完整结果分别记录，避免恢复时重复付费。

历史复用：从 `Refactor0830:eoh_rag/fme/rq1b_resume_transport.py` 抽取“请求前预算预留”的设计，从 `rq1b_transport.py` 抽取非敏感请求身份和完整响应 checkpoint 的设计。不得导入原类、旧 EvidenceJournal、分析请求或九次恢复策略。

### A2. 统一评测进程生命周期

- 处理官方 EoH 外层进程和 SubprocessEvaluator 内层进程的嵌套关系。
- Windows 上必须由能够清理整棵子进程树的组件拥有取消责任；仅把内层 timeout 调小不能作为全部保障。
- 进程超时、协议异常、候选异常分别归类，任何情况都不能留下无限运行候选。
- 保留数值执行白名单。AST 约束和进程隔离不宣称为完整的恶意代码安全沙箱。

### A3. 修复技能发布边界

- EoH 最优候选重评无效时只保存诊断，不发布 exported_skill，不因目录存在报告成功。
- 版本目录不可变。采用可靠的版本引用/索引发布方案，避免先删除旧导出再替换的空窗。
- 明确加载器与现有 code.py + 元数据导出接口的兼容方式；不要用两次独立文件替换冒充整份 skill 原子发布。
- 区分运行最优、最好生成版和导出引用，允许运行最优仍为基线或显式父本。

### A4. CI 边界

- 核心 Python 3.11 检查只安装最小依赖，验证不导入旧研究框架。
- EoH 可选检查单独安装固定提交的 extra，并运行适配器检查，不能静默 importorskip 后视为通过。
- 保留主 loop 与 EoH 的独立入口和依赖边界。

交付：统一执行合同、EoH 有界运行入口、可靠导出和对应 CI。

验收：只覆盖已发现的请求/认证/进程清理/无效导出/发布失败分支；本地 fixture 和必要的 localhost stub 足够，不用付费 API 验证这些工程故障。通过后停止，不扩成全仓库回归。

## 4. 实施批次 B：框架化现有 CVRP，保持行为不变

优先级：P1。依赖 A。

### B1. 定义 ProblemSpec

合同至少包含：problem_id、接口及版本、任务说明、baseline、suite 构建/加载、suite hash、约束验证、目标方向、执行能力白名单、结果与错误格式。

主循环不再直接依赖 CVRP 常量。解的构建、可行性和目标计算由可信问题评测器拥有，模型只修改明确授权的算法入口。

第一步只将当前 CVRP 接到新合同，不更换 seed、三个实例、目标计算或基线，不同时引入第二个问题。

### B2. 分离 SearchPolicy

把父本选择、算子选择、EDIT TARGET、接受和停滞规则从 I/O 与持久化中分离。默认实现保持现有单 incumbent + 最近一轮反馈，不新增模型控制器。

反馈关系应明确绑定来源 attempt/code hash。反馈消费统计区分准备、发出请求、收到回复，不能把“构建了 feedback 对象”直接当作已完成反馈后的生成。

### B3. 明确可比较身份

运行配置同时绑定问题接口、套件、评测器、搜索策略配置、模型请求配置和来源代码版本。评测器身份应覆盖影响评测语义的必要实现，不只依赖一个文件名。

交付：ProblemSpec、默认 SearchPolicy 和现有 CVRP 实现。

验收：现有保存代码在同套件的逐实例分数保持一致；i1/e1/m1、全失败、预算和导出语义不变。结构重构不需要另跑一轮 live 来证明代码整理成功。

来源目录只是供人工选择，不构成自动检索池。旧均值、confirmed 标记和研究报告不迁入新评分或 prompt。接口不兼容时明确报告；若要改写代码，应作为新版本重新评测，不能悄悄修补后仍称原始算法。

### C2. 资产身份与复用报告

算法身份与评测身份分离：同一份代码可以有不同套件的评测，但成绩必须绑定对应套件和评测器。用户指定父本时仍要在本次套件重新评测。

报告说明导入来源、重评有效性和当前分数，不把历史好成绩当作新运行收益，也不将导入父本计入本次生成数。

交付：显式导入合同和可追溯算法资产。不需要知识库或 UI 平台。

验收：一个指定候选导入后能重载重评；无效候选不进入可复用集合。go6 已有的父本续跑证据可保留，不为相同路径重复付费。

## 6. 实施批次 D：引入第二个问题，验证真正的框架接口

## 7. 实施批次 E：扩展一种算法搜索空间

优先级：P2。建议在 D 选择并完成 TSP 后实施，不与问题抽象同时改。

目前进化对象仅是下一节点选择函数。第一项扩展选择一个可信局部搜索原语，例如 2-opt，让模型进化一个明确的邻域选择/排序或有界调用规则。先固定一个新入口，不同时开放整套求解器。

可复用 main/0830 共用资产：

- `scripts/evaluate_tsp_nearest_two_opt.py`
- `scripts/evaluate_tsp_relocation_vnd.py`
- `scripts/evaluate_tsp_or_opt_2_vnd.py`
- `scripts/evaluate_tsp_restricted_three_opt.py`
- `eoh_rag/search_control/tsp_controller.py` 的原语白名单及预算校验思想。

只抽取选定原语、必要路线检查和必要测试。不导入旧 controller 的 sys.path/script 依赖链、portfolio、教师上界、探针或研究入口。

固定原语负责合法操作和正确目标计算；生成代码只控制授权决策。局部搜索次数/操作预算与墙钟一起记录，不能通过无限多次调用固定优化器获得隐性计算优势。

交付：一种新的算法接口及其执行合同。报告区分固定原语和模型生成部分；已有手写 2-opt 的改善不归因给模型发明。

验收：路线合法、执行有界、反馈对应本轮候选、代码可重载。不要求胜过 construct 基线；两者的计算预算不同，不能直接作公平性结论。

## 9. 最小验收与预算纪律

- Python 和 CI 保持 3.11，不升级解释器作为本轮重构的一部分。
- 优先实现；每批只检查新改动影响的合同，不累计低价值测试数量，不反复运行无变化已通过的检查。
- 现有具体失败必须有针对性保护；更广的压力测试、进程故障注入、长运行先说明范围并取得用户确认。
- fixture 是接线证据，真实模型运行是自主生成证据，源码核对和实际执行结果分别注明。
- 所有 live 运行单独授权模型、请求/候选/墙钟预算。默认三候选保持不变；十轮已有产物不构成后续自动扩大预算的授权。
- 任何运行不得因无改善或全失败自动追加额度；结果未知的请求不得自动重发。
- 不以相对 13.519、12.356、go5/go6 或官方 EoH 的提升作为工程门槛。

## 11. 暂缓的研究与产品工作

中断恢复仅在长运行确有需要时实施，恢复不得重置预算；历史 checkpoint 仅用于精确身份与已完成响应，不自动授权未知请求重试。

完成工程里程碑后，可另立“真实反馈是否优于独立重复生成”的同预算研究。未参与搜索的数据、重复实验、统计分析、多模型和迁移均属于该独立阶段，不是当前入场券。

默认不增加可视化平台、自动科研报告模型调用或长期后台实验。先保证用户给定问题后，无需逐轮介入，算法能根据真实执行结果持续修订，留下可重用代码并在授权预算内停止。
