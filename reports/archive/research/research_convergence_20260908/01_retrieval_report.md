# 科研路线检索报告：从多线探索收敛到算法 skill 进化

日期：2026-09-08。仓库：`auto-algo-opt`。分支：`Refactor0830`。审阅基线：`c8cb66cd09d3829bfdf254d00d117fe35cfd6410`。

## 核心判断

建议把当前工程主线定为：**固定的 agent loop + 可执行启发式 skill 的生成、实际评测、反馈修订与持久复用**，首个问题采用 CVRP。按用户后续收紧要求，在新分支抽取问题/评测和生成能力，重写独立小内核与journal；不沿用FME包或其前瞻分析校验，不训练控制器或同时进化提示、工具与科研工作流。

实施约束以[执行计划v3](02_execution_plan.md)为准：输入是问题和固定3个开发实例，初始来源仅基线或用户显式指定的一个parent skill，导入代码在新套件重评；历史报告/失败经验不进入prompt。完成定义为多轮生成、独立评测、真实反馈被下一轮消费以及预算停止，全失败也可跑通闭环，终态no_valid_candidate，不以基线冒充生成结果。有效候选才导出可重载skill。Python 3.11下新包可import、四组内核pytest与no-API smoke是必需门槛；fixture只证明接线，真API须在fixture通过后另获用户授权。Refactor0830及远程默认保持现状，删除只在新分支执行。本报告的历史检索结论不因此改写。

这解决的是工程目标“能够跑起来”，并不承诺算法效果。论文主张需要后续证据；“我们做了一个 agent loop”本身没有足够新颖性。推荐下一阶段只追问执行反馈如何改变算法 skill 的有效性与复用成本。

最终整理为 **31类路线、93个manifest逐一映射、58个可定位历史阶段**，并单独说明D0–D32精选回流与缺失原件。完整路线与细分实验见 [03_route_catalog.md](03_route_catalog.md)，实施方案见 [02_execution_plan.md](02_execution_plan.md)。逐文件快照见 [04_repository_inventory.csv](04_repository_inventory.csv)。

## 1. 检索范围与证据等级

采用四个 GPT-5.6 Luna 子 agent 分工审阅历史档案、旧框架代码、实验/策略资料、FME/最新证据；主控负责全量目录盘点、上游文献/代码检索、关键调用链复核和收敛决策。没有调用任务无关的 skill 或插件。

审阅开始时盘点了 **957 个本地文件**：941 个 Git 跟踪文件，15 个非忽略未跟踪文件，1 个被忽略的本地演示稿检查文件。排除 `.git` 内部对象；包括用户已有的 `reports/optical_transfer/`。清单不包含本轮新增报告。对研究代码、方案、manifest、紧凑结果和阶段摘要作分工审阅；图片/PDF/演示稿以其对应源码、结构文本或同内容报告定位研究路线，没有逐页视觉审阅。目录全量盘点不等于每个二进制字节都经人工语义阅读。

证据分四类，后文不混用：

- **当前代码事实**：现在的函数、入口、依赖和静态分支确实存在。
- **仓内历史结果**：Git 保留的精简结果、审计回执、报告可读，但本轮未重新跑 solver。
- **提案/文献关联**：有设计或理论来源，不代表已经集成或有效。
- **缺失原始证据**：`outputs/` 当前不存在，外部 Obsidian 路径和旧电脑目录未自动纳入；不能把精简审计回执说成这台机器重新完成的原始账本复核。

这里的“路线完整”指当前工作树可定位的路线、历史阶段与 manifest 均纳入目录。已经从 Git 删除且仅存在外部盘、其他未检出分支中的探索，无法仅凭当前工作树保证穷尽；不为追求表面完整自动恢复所有旧分支或下载大型数据集。

## 2. 为什么原来的主线不断变复杂

仓库同时积累了四种不同的优化对象：启发式函数本身、提供给生成器的策略/记忆、选择算法或算子的控制器、决定下一步研究动作的科研控制器。这四层都能单独形成项目；把它们同时放入闭环，会让一个结果需要同时解释算法质量、提示质量、选择质量和研究判断质量。

另一个问题是证据语义不一致：旧 EoH 的目标值/基线 gap、TSP 大规模 Core 的运行时间与质量合同、FME 的独立合成实例、RQ1b 的行为预测与 Potential-AUC，都不在同一标尺上。旧四行 605-run 最优结果不能作为新 FME 的同预算胜率，新行为 AUC 也不能代替实际算法改善。

当前 README 宣称唯一顶层 `FMEResearchLoop`，源码确实使用这一组件，但其中 `FMEController` 按预设的分数/成本规则选动作，并未学习或估计真实信息增益。模型参与候选生成与前瞻分析，不等于模型已经自主设计整个科研流程。参见 `eoh_rag/fme/controller.py` 与 `research_loop.py`。

## 3. 对最新证据的判断

### 已有执行链，不代表核心机制成立

仓内 v7 报告记录 RQ1–RQ4 在线 pilot 完成 81/81 坐标、935 次候选尝试、738 个有效候选；报告说明主动控制、相关历史、跨问题抽象提示、较大模型都没有建立稳定的额外收益。它支持“曾经完成这套执行与记录流程”，不支持所有研究假设。

证据：`eoh_rag_workspace/reports/refactor0830_online_review/online_review.json`、`agent_records/calibrations/refactor0830_v7_result_review_20260831.json`、README 的最新结果摘要。本地原始 `outputs/fme_pilot/...` 不在当前工作树，本轮没有重做完整实验审计。

RQ1b v2 完整续跑的 Git 审计回执记录 24 单元、384 候选尝试、36 条同代码诊断、809 次 HTTP；续跑复用 333 个成功响应，是原 cohort 的延续，不是一个独立重复实验。README 汇总 C−B：行为准确率 −0.93 个百分点、有效候选率 −5.47 个百分点；虽 Potential-AUC 配对中位 +1.24 个百分点、held-out 中位 +0.52%，科研继续门槛未通过。

审计文件里的 `scientific_claim_allowed: true` 是记录协议允许分析该批结果的字段，不能读成“有正向科研结论”。`evidence_integrity_verified` 也只描述完整性。以上数字和五项门槛还可直接定位于 `agent_records/calibrations/rq1b_v2_resume_delivery_20260831.json` 的 `primary_C_minus_B`、`gates`；其 scientific_status 为 `inconclusive_mechanism_not_established`。

合理推论是：暂停扩展这些假设，先降低执行链中额外分析与控制的负担。不能据此断言“所有反思都无效”——RQ1b 检验的是特定的评测前行为预测与被动回流，而拟议小循环使用评测后的真实数值/错误反馈，两者不是相同干预。

### 具体的工程耦合

1. `online_pilot.py:PilotCell.generate` 总会请求并解析前瞻分析，然后才评测候选。scalar 臂只是不把分析回流，并不是没有分析调用。结构化分析失败可能消耗候选槽并挡住有效代码的评测。
2. `online_pilot.py:load_protocol` 强制三问题，且依赖冻结历史文件；`fme_pilot.py` 默认是完整 v7 协议。简单改几项 CLI 参数不能变成独立单问题小循环。
3. `online_adapters.py:verify_journal` 对旧候选评测事件要求对应前瞻分析。新简化链若绕过分析，需要自己的事件合同，而不是把校验删除后仍宣称遵循旧协议。
4. `FMEArchives`、RAG card、候选 population 各自保存了不同信息；没有一个已经完成“独立导出、重载、再次作为父 skill 使用”的统一轻量接口。

这些是实施计划需要解决的具体差距；不需要先再做一轮科研实验才能确认。

## 4. 有界文献检索

检索目标是选择最小可用设计，而非写系统性综述。共使用 10 个有针对性的搜索查询，并直接打开原论文/作者代码；已有充分决策依据后停止扩展。只引用论文、官方会议页与作者仓库，不把搜索摘要里的宣传性增益当成本仓库预期。

| 文献 | 真正优化的对象 | 对本仓库的作用 | 当前决定 |
|---|---|---|---|
| FunSearch，2023 在线发表 | 固定求解骨架内的函数；执行评分与程序库构成搜索循环 | 支持固定评测器、只进化关键代码的最小边界 | 借鉴边界；不搭大型岛模型基础设施 |
| EoH，ICML 2024 | 自然语言 thought 与启发式代码 | 仓内已经 vendored，生成模板和提取器可直接复用 | 作为现有生成底座 |
| ReEvo，NeurIPS 2024 | 启发式种群，短期/长期文字反思 | 与算法修订最接近，也是未来必须区分的强相关工作 | 借鉴实测反馈；当前不完整移植双层反思 |
| Voyager，2023 | 可执行技能库及迭代程序改进 | 帮助界定 skill 必须能执行、保存、检索和复用 | 借鉴 skill 资产语义；不搬 Minecraft 环境 |
| GEPA，2025 预印本 | 一个或多个文本组件，借助执行轨迹反思更新 | 后续提示/skill 文本进化的清晰适配接口 | 当前保持提示固定；以后需要时才集成 |
| ADAS，2024 | agent 的代码、控制流及组合 | 对应“整个 agent 自进化”，搜索对象更大 | 当前不选 |
| AFlow，ICLR 2025 | 代码表达的 agent 工作流，用树搜索修改 | 对应工作流层面的自动搜索 | 当前不引入 MCTS 与工作流图 |
| AlphaEvolve，2025 | 经自动评测的算法/代码改进 | 说明执行器和明确评分是算法发现的重要基础 | 参考架构，不复刻完整系统规模 |
| CRUXEval，ICML 2024 | 代码输入/输出推理的测量 | 解释 RQ1b 行为预测来源及其与性能的区别 | 保留为历史测量参考，不作为小循环门槛 |

### 原始来源与可迁移边界

**FunSearch**：初始程序、可计算的 evaluate、程序库、LLM 生成形成闭环；论文讨论固定骨架、只进化关键函数可集中搜索。该结论支持我们的工程选择，不能保证 3 次候选有效或改善。[Nature 原文](https://www.nature.com/articles/s41586-023-06924-6)

**EoH**：以自然语言表达启发式思想，再由模型转为代码，在进化框架内共同演化。仓内已经具备其问题接口与代码生成部件，因此重用成本低；当前版本的历史结果不能直接等同论文复现。[ICML/PMLR 原文](https://proceedings.mlr.press/v235/liu24bs.html)

**ReEvo**：把进化搜索与反思结合；作者代码 `ReEvo.evolve` 实际串联选择、短期反思、交叉、评测、长期反思及变异。这与“用文字反馈修订启发式”高度重合，未来若提出新方法必须说明超出这条已有路线的具体贡献。[论文](https://arxiv.org/abs/2402.01145)、[作者实现](https://github.com/ai4co/reevo)、[已读核心代码](https://raw.githubusercontent.com/ai4co/reevo/main/reevo.py)

**Voyager**：技能是可执行代码，通过环境反馈、执行错误和迭代提示改善，并存入可持续检索的库。我们的技能对象是组合优化启发式，未实现其自动课程，也不外推其跨世界迁移成绩。[论文](https://arxiv.org/abs/2305.16291)、[作者代码](https://github.com/MineDojo/Voyager)

**GEPA**：从执行轨迹提取反馈，对文本组件提出修改并评价。作者当前 `GEPAAdapter` 的关键接口为 `evaluate` 与 `make_reflective_dataset`，候选为命名文本组件的映射，分数约定越高越好。若以后接入 CVRP 最小化目标，需要转换方向；现在无需增加这个依赖。[论文](https://arxiv.org/abs/2507.19457)、[作者代码](https://github.com/gepa-ai/gepa)、[已读 adapter 接口](https://raw.githubusercontent.com/gepa-ai/gepa/main/src/gepa/core/adapter.py)

**ADAS**：meta agent 编写新 agent 的代码，以历史设计档案支持搜索。它的控制流/工具组合搜索比我们目前的启发式函数搜索广得多；一开始采用它会把“能跑”变成多个未知接口的联合调试。[论文](https://arxiv.org/abs/2408.08435)

**AFlow**：把 agent 工作流表达为代码并用 Monte Carlo Tree Search 搜索修改。当前不存在必须优化工作流拓扑的已验证需求，因此只用来划清研究边界。[论文](https://arxiv.org/abs/2410.10762)、[作者仓库](https://github.com/FoundationAgents/AFlow)

**AlphaEvolve**：通过自动评测反复提出、执行和改进算法代码。这支持“把评测器当作可信反馈接口”的共同设计原则，不说明本仓库需要复制它的全部采样、调度或模型规模。[论文](https://arxiv.org/abs/2506.13131)、[官方介绍](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)

**CRUXEval**：测量短 Python 函数的输入和输出推理。仓库 RQ1b 借鉴输出预测定义，自行构造 CVRP 干预状态，不能称为原 benchmark 的成绩，也不能将局部状态预测直接等同整条求解轨迹的理解。[ICML/PMLR 原文](https://proceedings.mlr.press/v235/gu24c.html)

上游作者仓库链接指向检索时主分支，不是已经锁定的依赖版本。本轮没有下载、安装或运行这些仓库，也未审阅其全量代码；具体实现判断仅限明确列出的核心源文件。真正集成时应锁定提交，当前方案不依赖其新增 API。

## 5. 三个选择的取舍

| 选择 | 需要新增的核心能力 | 对当前目标的适合程度 |
|---|---|---|
| 固定 loop，进化可执行算法 skill | 小 runner、skill 保存/加载、实际反馈闭环 | 推荐：能够复用最多现有部件，结果对象清晰 |
| 固定求解程序，进化提示/策略文本 | 文本变异与评测适配、提示版本选择 | 次选：适合后续研究，但目前还没把最小运行与可复用资产统一 |
| 同时进化 agent 控制流和工具/技能 | meta evaluator、程序/工具合同、工作流搜索 | 暂缓：扩大优化对象，难以解释失败来自哪里 |

保留一个简单正常生成/失败修订策略并不妨碍以后接入 GEPA 或学习控制器。相反，它先固定运行、成本和资产的含义，使新增变量可以被单独研究。工程实现阶段不复活已经暂停的 RQ2–RQ4、TOCC、专家路由或大规模 TSP 组合矩阵。

多 agent 审阅提出过两类更重的建议：沿用完整的 prospective/FME 机制门禁，以及先通过多环境 confirmation/held-out 再保存 skill。主控没有将它们采纳为首版要求，原因是它们服务旧科研假设，超出“先跑通、暂不要求效果”的当前目标。采纳的是动作真实性、技能实际消费回执、版本谱系和错误留痕。固定策略的 agent loop 不声称具备自主科研决策；可执行但更差的 skill 可以保存，分数和范围必须如实标注。
