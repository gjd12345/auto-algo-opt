## 验收范围

v1 的主入口是 Coding Agent 加载 Algorithm Optimization Skill 后操作 Session Runtime。状态、预算、任务生命周期、身份和证据由 SQLite-backed Runtime 控制；官方 EoH 只负责轮内种群搜索、候选生成及显式开启的有界修复；候选结果必须经过确定性隔离评测。

已移除的旧模型驱动外层 Workflow、Plan/Evaluate 角色适配器和专属测试不再属于产品路径。CLI 的 `workflow` 子命令仅保留一个 release 过渡期 tombstone，返回 `WORKFLOW_DEPRECATED`，不会发起模型请求。

Memory 是可插拔横切能力：Plan 可以搜索和读取正文，Evaluate/Runtime 可以提交建议；Memory 版本化、可选、失败不应伪造候选结果，也不会默认混入其他问题的条目。Session 只冻结 EoH 搜索策略的默认值和 limits，Plan 可逐轮请求 `pop_size`、`n_pop`、`max_sample_nums` 的边界内调整，Runtime 会把 effective policy 写入 round context 和 receipt。

## 必须通过的证据

- `py -3.11 -m pytest -q`：当前仓库的 kernel、官方 EoH adapter 和 Session integration 回归；本次修复后的本地全量预检结果为 `163 passed, 1 skipped`。远程 CI 结果需以 RC 提交后的流水线为准。
- `py -3.11 tools/validate_skill.py skills/algorithm-optimization`：Skill frontmatter、引用和结构校验。
- `py -3.11 -m agent_skill_loop smoke --problem cvrp_construct --output <new-output>`：无外部 API 的官方 EoH + 确定性评测链路。
- `session init/state/submit-plan/execute/collect/submit-evaluation/finish-round/stop`：以 `state_version`、`operation_id` 和审计证据保证可恢复性。

本 cleanup gate 不重新发起 DeepSeek 付费长跑，也不把历史 live 产物当作本次代码变更的实时证据。真实 API 是否成功，应使用新建的、身份匹配的 Session 单独记录。

## 可靠性承诺

1. 外部请求在发送前由 Runtime 统一预留并记账；超时或未知结果不退款、不自动重发。
2. provider 终止性错误、截止时间、预算耗尽和证据写入失败都有显式终态，不以基线或假的 Evaluate 结果收口。
3. incumbent 只能由同一套件下的可信评测证据更新；更差候选不覆盖当前最好资产。
4. 有效 Skill 导出 `code.py`、元数据和证据身份；重新进程加载后必须在同一套件重评。
5. Runtime/Skill identity mismatch 时只允许读取证据和停止，不得编辑 SQLite 绕过门禁。
