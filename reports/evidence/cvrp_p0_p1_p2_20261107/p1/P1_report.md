# P1：C6 容量惩罚与候选竞争范围

**C6 的近似平局分支确实经常把选择推到掩码外，但没有观察到稳定的距离收益。** 在 200 客户的新样本上，C6 原版和将容量惩罚扩到全部候选的版本都比无惩罚版本更长。

冻结 C6 的 0.60 仓库距离系数、原始需求平局项、近似平局阈值和 0.01 容量惩罚系数。V0 去掉容量惩罚，V1 是原始 C6，V2 在触发时只允许掩码内候选竞争，V3 在同一触发条件下给全部可行候选加惩罚。V2 沿用 V1 的系数与惩罚函数，没有沿用原 C7 的额外封顶。

50、100、200 客户各 40 个新实例，四版共享同一规模内的实例。正式距离由原 Evaluator 计算，之后通过同一评测路径重放每一步以记录选择、掩码、基础分、惩罚和修正分。56,000 个客户选择步骤的重放按实例与正式评测距离逐项吻合。日志记录的是候选函数被调用的步骤。

差值为候选减参考，负值表示更短。95% 区间为规模内配对实例 Bootstrap 百分位区间，每组 20,000 次抽样。V2 在三个规模均未出现掩码外选择。V1 在 612 次触发中有 559 次选择掩码外节点，约 91.3%。其原因在评分规则上可以解释：掩码内候选承受非负惩罚，掩码外候选仍以原始分竞争。容量项除以当前距离，距离较小时惩罚还可能放大。这解释了机制怎样改变排序，不能单独解释各实例的距离变化。

V2 与 V1 的差值区间在三个规模都跨零。50 客户的 V1 与 V0 只相差 −0.00983，区间覆盖双向变化。200 客户时，V1 与 V3 分别比 V0 长 0.35029 和 0.95544，配对区间均在零以上。因此，C6 的主要留出表现不能归功于这个容量惩罚。基础评分 V0 本身已值得保留为比较对象。
