02 · 三个问题

模型只设计一步规则，外围循环由评测器固定

bp_online

在线装箱

函数 score(item, bins) 给可行箱打分，分数越高越优先放入。

Weibull 物品流，箱容 100。目标是相对 L1 下界的 excess，越小越好。

tsp_construct

旅行商问题

函数 select_next_node 从当前城市选下一个未访问城市。

50 个随机点，8 个实例。目标是平均回路长度。

cvrp_construct

带容量车辆路径

函数 select_next_node 选下一个客户，也可提前回仓开新车。

50 客户 + 仓库，容量 40，16 个实例。目标是平均总路程。

起点都是简单规则：装箱用剩余容量当分数，TSP / CVRP 用最近邻。后面看到的改善，都是模型在这个固定接口里改出来的。
官方 EoH ICML 2024 评测器 · 实例 seed=2024
03 · 大模型怎么进化

先写可运行函数，再按分数改骨架和参数

① 注入契约和策略卡API 规则 + 两张文献卡，告诉模型函数签名和可参考想法
→
② 第 0 代写 3–6 个函数一句话算法描述 + Python 实现，立刻在固定实例上打分
→
③ 四算子继续改换形态、抽骨架、改结构、调参数，评测后留下更好的
→
④ 写入共享池该 run 最优代码供其他岛后续使用
e1
换形态

写出与父代完全不同的新算法。

e2
抽骨架

先找父代共同点，再写受其启发的新算法。

m1
改结构

在一个父代上做可识别的结构修改。

m2
调参数

识别主要数值，改阈值和权重。

05 · 在线装箱最优 run

前 7 代最优停住，第 8 代一次改写打到 0.00674

第 0 代已有雏形 0.02324

residual = bins - item
utilization = item / (item + residual)
forbidden = (residual > 0) & (residual < item)
score = utilization - residual**2 / (item + 1)

行为：奖励装得满，并惩罚留下小于一件物品的空隙。已经优于基线 0.0398，但还不是最终公式。

第 8 代保存代码 0.00674

residual = bins - item
utilization = exp(item / (residual + item + 1e-9))
penalty = ((residual > 0) & (residual < 2*item))
         * (residual - item)**2 / (item + 1e-9)
score = utilization - penalty

实际变化：利用率改成指数；惩罚落到中等正残差。恰好装满不罚，留下以后还能放下同类物品的空隙。

最终选择器在做什么

对每个候选城市打一个加权分：当前边长度、从该点出发用最近邻走完剩余点的路径估价、最好/最差距离之差、过长边惩罚。

剩余点很少时退回最近邻。完整滚动代价较高，这是静态复杂度判断，不是计时结果。

if current == depot:
    return farthest feasible customer
if rest_capacity / (2 * max_demand) > 0.4:
    maximize savings
    d(depot,u)+d(depot,current)-d(current,u)

09 · 怎么读这些结果

三条最优轨迹说明系统会改启发式，分数仍绑在旧评测上

一句话：装箱把 excess 从 0.023 收到 0.00674，TSP / CVRP 各缩短约 8.5%。改善来自可执行代码和固定实例打分，不是报告文字。
01看机制

装箱惩罚中等残差，TSP 做剩余路径滚动，CVRP 用 farthest-first + savings。

02看代数

装箱靠第 8 代一次改写；TSP 在第 4 代已接近最优；CVRP 需要 gen=16 的后半段。

03看边界

共享池相关、旧基线、构造接口。换套件必须重评，不能继承这些分数。
