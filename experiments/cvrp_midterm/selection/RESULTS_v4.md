# Task B, revision 4: frozen A/B/C in the pool, cost-sensitive selection

Generated by `report_tables.py` from `summary.json`, `selectors.json` and the archived v2 outputs. Reproduce with `run_matrix.py` then `select.py`.

Revision 4 changes three things against revision 3: all three frozen PoC rules (A, B and C) are in the pool instead of C only, every rule now carries a measured runtime and a per-instance rank, and the pairwise selector family is fitted twice, with and without cost-sensitive weights, so the ablation is visible.

## Design

Three binary factors crossed, demand distribution held fixed at U{1, 9}: spatial = uniform/clustered, depot = centre/eccentric, capacity = loose/tight. 12 instances per cell, 50 customers, 96 instances total.

Capacity levels are fixed integers: {'loose': 45, 'tight': 28}. Every factor moves one thing only, so a main effect is attributable.

The three frozen pointwise rules are added verbatim and the builder refuses to run if a byte moves:

`gain vs fixed` is the objective saved against committing to the single best rule of that portfolio (10,000-draw paired bootstrap 95% CI and one-sided p-value).  In the A/B/C pool the highest point estimate is **pairwise_loo_unweighted** at +0.94%, while every selector in the older C-only pool still loses.  Crucially, the 1-feature `cluster_stump` matches or beats all 8-feature learners because the dominant complementarity is spatial (`uniform -> A`, `clustered -> B`), and the 8-feature learners' 95% CIs still cross zero.

The cost-sensitive variant (`pairwise_loo`) weights each pairwise observation by `|c_a - c_b| / mean|c_a - c_b|`; `pairwise_loo_unweighted` is the revision-3 recipe that only fits the sign.  Both are reported because neither dominates: the weighted version is better in the narrow pools, the unweighted one is better in the A/B/C pool.
