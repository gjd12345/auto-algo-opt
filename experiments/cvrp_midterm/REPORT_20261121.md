## 1 · 任务 A：把两个因子分开，然后跑两批

### 1.1 为什么第一批不能算数

`a1` 的 guided 文本里 `GUIDED_OPERATIONS` 写 "replace the absolute epsilon band with a relative
band `1e-3*span`"，`FINDING` 写 "replacing the band by `1e-3*span+1e-12`"——**两个因子指向同一条
一行补丁**。证据：`a1_finding_only` 第 1 轮 `candidate_5` 只有 741 字节，是冻结 C 原文加那一行；
`operations_only` 与 `guided` 在 4 个实例中的 3 个上产出与 C 完全相同的代码。三臂共享套件成绩
11.061–11.081，差 0.02–0.2%。详情见 `runs/RESULTS_BATCH1.md`。

### 1.2 第二批的设计

只改两段文本，其余逐项相同：

- finding（781 字符）：只讲测量与代价——band 触发率 1.3%→64%→83%、归一化目标
  10.92→16.20→33.52（+48%/+207%）、纯比例修法 spread 0.39% 但标称尺度 +1.92%。**无代码、
  无表达式、无规则名。**
- operations（523 字符）：只讲搜索操作——每轮只替换一个分数线项、加一个廉价的次级排序阶段、
  保持可行性与接口。**不出现 scale/band/margin。**
- `plan_alignment` 四臂固定 `"aligned"`，避免引入第三个因子。

四臂 = control（无/无）、finding_only（无/有）、operations_only（有/无）、guided（有/有）。
两批独立复制：`a2_*`（12:40–12:47）与 `a3_*`（12:55–13:06），预算 4 轮 / 24 请求 / 120 求解 /
每轮 6 请求 / `request_timeout=600` / `deepseek-flash` / Memory 关 / `eoh_thinking="disabled"` /
benchmark `eohs_v1/cvrp_construct_mini`。

判分有三条线，必须分开：运行内 gap（4 实例、对本次 seed，是适应度不是可比量）；共享套件
（6 实例 `dev_suite.json`，同一评测器重打每个候选）；两条参照线——冻结 C **10.9197**、本次搜索的
seed **NN 12.1150**（`baseline_code_sha256 = 90b23362…` → `p0/frozen_code/NN.py`）。

**搜索不是从 C 出发的**，而 finding 描述的是 C 的缺陷。这条错位是本轮最重要的结构性发现。

### 1.4 全部候选的分布（能做归因的量）

按源码去重、去掉每轮复制的 `baseline` 副本，同一评测器同 6 实例重打，两批合并：

| 臂 | n | p10 | 中位 | p90 | 最好 | 低于 seed | 中位对 C | 中位对 seed |
|---|---|---|---|---|---|---|---|---|
| control | 40 | 11.5914 | 12.3935 | 15.2311 | 11.4229 | 15 | +13.50% | **+2.30%（比 seed 差）** |
| finding_only | 39 | 11.5853 | 12.4677 | 16.1485 | 11.2652 | 10 | +14.18% | **+2.91%（比 seed 差）** |
| operations_only | 31 | 11.4458 | 12.1150 | 12.6479 | 11.1126 | 15 | +10.95% | **0.00%（等于 seed）** |
| guided | 34 | 11.3960 | 12.1109 | 14.4932 | 11.2343 | 17 | +10.91% | **−0.03%（等于 seed）** |

三条比头名更可靠的读法：

1. 拿到 operations 指导的两臂中位数停在 seed 水平，没拿到的两臂掉到 seed 以下 2–3%（两批都
   成立；a2：+1.80 / +3.86 / 0.00 / −0.11，a3：+3.59 / +2.41 / +0.29 / +0.20）。
2. 最好的候选也没有接近 C：搜索把 NN 改好约 8%，改到的位置仍比 C 差 1.77%——**它是在重新发现
   C 所在的位置，不是超过 C**。
3. 指导的作用主要是**收窄坏尾**（p90 15.23/16.15 → 12.65/14.49），不是"找到更好的"。

### 1.6 候选里写了什么

| 臂 | 最好候选 | 结构 |
|---|---|---|
| control | a2 r4 c3 | `d_cur*(1+0.8*closeness) − 0.9*d_dep*fill + 1.4*d_cur*(1−fill)`，长度与无量纲 `fill` 直接相加 |
| finding_only | a2 r2 c2 | 除以 `span=max(dm)`，注释 "no absolute-length term; scale free"，再 `d_cur − 0.30*saving − 0.20*util − 0.10*tightness` |
| operations_only | a2 r1 c5 | 11 行，`savings = d_dep − d_cur` 取 argmax，`order` 是死代码 |
| guided | a2 r3 c1 | `scale=mean(d_dep)`、`saving=(d_dep+d_cd−d_cur)/scale`、`score=−saving+0.30*proximity−0.20*fill` |

- **没有人重复被否定的补丁**：149 个候选里 `mixed_units` 0、`relative_with_epsilon` 0（a1 的 10 个
  来自提示词泄漏）。
- **只吸收权衡的第一半**：都去掉了绝对项，没有人处理"纯相对修法标称 +1.92%"这第二半。
- **改写的对象不是被分析的规则**：a1 的 finding 带 C 的公式，Agent 才能抄回 C 打补丁（那才是
  −8.35% 的来源）；a2/a3 抽掉公式后通路消失。

## 2 · 任务 B：修正 savings 与测试床后重做

### 2.1 上一版的两个错误

1. `selection/run_matrix.py` 的 savings 写成 `dep[u]+dep[u]−cur[u]`，仓库距离用了两次；正确是
   `S(i,j)=d(i,0)+d(0,j)−d(i,j)`，起点处节约量应恒为 0。修正后 `savings` 立刻成为最强规则，
   v1 的"分工况最优轮换"是错误 as-if 的产物。
2. `eccentric` 工况同时改了仓库位置、容量（40→30）、需求范围（1–9→3–9），无法归因。

v2 改成三因子全交叉（需求分布固定 U{1..9}，50 客户）：`spatial ∈ {uniform, clustered}`、
`depot ∈ {centre, eccentric}`、`capacity ∈ {loose 45, tight 28}` → 8 工况 × 12 实例 = **96 实例**。
规则 7 条：`nn`、`savings`（节约量启发的逐点构造，**不是完整 Clarke–Wright**，无合并、容量由
harness 过滤）、`dd_load`、`radial`、`farthest`、`isolate`、`load_fill`（后两条结构不同，用于检验
互补是否只是组合太薄）。v1 产物归档在 `selection/v1_20261121/`。

### 2.2 结果

| 指标 | 数值 |
|---|---|
| 规则均值（越小越好） | savings 13.2721 < radial 13.8571 < dd_load 14.2026 < nn 14.3962 < isolate 18.4507 < load_fill 19.8927 < farthest 38.0059 |
| VBS（逐实例最优） | **1253.7384** |
| SBS（固定最优 = savings） | **1274.1252** |
| SBS→VBS 间隙 | **1.63%**（v1 为 4.23%） |
| oracle 归属 | savings 59、dd_load 17、nn 10、radial 10 |
| 新增两规则是否赢过 | 一次都没有（core-4 与 extended-6 的 VBS/SBS 完全相同） |

- `savings` 在 **8/8 工况都是最优固定规则**；逐工况 gap 从 0.32%（uniform_eccentric_tight）到
  **2.82%**（clustered_centre_loose）。**loose 容量的互补空间（2.57%）大于 tight（0.92%）**。
- 因子主效应（每格 48 实例均值）：uniform 15.892/14.567（nn/savings）vs clustered 12.901/11.977；
  centre 11.927/11.016 vs eccentric 16.866/15.528；loose 12.343/11.452 vs tight 16.450/15.093。

### 2.3 选择器（关键负结果）

| 选择器 | 总路程 | 相对 VBS | 选中分布（nn/savings/dd_load/radial） |
|---|---|---|---|
| 固定最优（SBS） | 1274.13 | 1.63% | 0 / 96 / 0 / 0 |
| 1-NN（LOO） | 1293.25 | 3.15% | 12 / 54 / 20 / 10 |
| 岭回归（LOO） | 1277.03 | **1.86%** | 2 / 84 / 8 / 2 |
| 岭回归（LORO，留一工况） | 1280.82 | 2.16% | 2 / 76 / 15 / 3 |

**修正 savings 之后，没有任何学习型选择器优于固定选择**（岭回归 LOO 多走 2.91，差 0.23pp；v1 是
"好 1.15pp"），1-NN 仍最差（3.15%）。LORO 最差 clustered_centre_loose 5.78%、最好
uniform_eccentric_tight 0.32%。岭回归 96 次里 84 次选 savings——它学到的是"几乎总选 savings，
偶尔换"，所以只能贴近固定选择、无法超过。结论：**"静态实例特征 → 规则选择"这条链在当前特征集下
没有可用信号**，论文里不能声称通用选择器；1.63% 是事后 oracle 的量，不是可兑现的量。

## 4 · 边界与风险

1. 真实 provider 不稳：a3 control 前 3 次尝试均 `PROVIDER_TERMINAL`（第 4 次成功）；a1 control
   重跑 2 次。废弃会话都在 `runs/_aborted/`。
2. 任务 A 每臂每批只有 1 个 seed；两批的极差已 1.28pp，**不足以支撑任何效应量**。
3. 任务 B 只有 1 个测试床种子（`20261121`）、规模固定 50；96 实例共享同一组 12 个点集/工况。
4. 选择器开销只算求解次数，未算特征提取（可忽略，论文要写清）。
5. 远程 CI 未在本次返回，`227 passed, 2 skipped` 仅为本地 pytest 结果。

## 5 · 下一步（按优先级）

1. **A：seed 与 incumbent 换成 C**。让 finding 指向的对象与实际被改的规则是同一个，否则
   "发现能否修复规则"测不到。这是唯一结构性的修法；不做这一步，加种子只是加噪声。
2. **A：若保持 seed=NN**，至少 6–8 个种子才能把 0.28 的位移从噪声里分出来。
3. **B：扩规模**（100/200 客户、第二个测试床种子），看 1.63% 是随规模变大还是收敛到 0；同时把
   "是不是完整 Clarke–Wright"的差别单独测一遍（合并式 vs 逐点式）。
4. **长程 8–12 轮继续暂缓**：四臂都在第 1–2 轮拿到全部差距，后两轮基本在重写同一结构，没有证据
   支持多给轮次会有额外收益。
