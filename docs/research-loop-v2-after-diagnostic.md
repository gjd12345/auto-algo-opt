# 三 seed 诊断之后的实施顺序

本文件是后续设计，不追加本批 900 次 solver 预算，也不解锁 heldout。当前里程碑的交付是恢复有改善空间的训练问题、完成真实外层 Agent 的 A/B/C 诊断，并说明能与不能得出的结论。

## 先解决实验可解释性

下一项优先工作是共同首轮历史的安全分叉，而不是换更复杂数据。相同搜索 seed 没有固定服务商输出，首轮三组在处理开始前已经有不同的 incumbent。应设计只读快照导入：冻结首轮候选、种群、事实、评测器和哈希；为每个分叉建立明确的导入 provenance，保留原始身份，不手工伪造本运行 evaluation_id。导入的共同首轮费用与后续预算如何计入，应在新预注册中明确。C 的 Memory 仍从空库开始，只允许本分叉处理后形成的经验。

同时为 A/B/C 使用独立的 Controller 上下文，记录实际模型身份、处理顺序和可报告成本。当前同一宿主跨运行阅读证据，虽然显式 Memory 库隔离，但不能宣称 Controller 语境完全盲化。需要隔离的是信息路径，不是要求三组输出不同文字。

验收先用已有事实验证：同一首轮输入可逐文件核对；分叉身份可追踪；C 不能读其他分叉 Memory；A/B 对比材料规则和字段相同。此时不需要新的真实 EoH 请求。

## 再查清 Plan 是否被执行

本次多次要求单项修改，却出现同时改变核函数、权重、精确装满和新箱处理的最终赢家。先利用现有 candidate code、execution delta 和 Plan 做离线内容标注：按“请求的改动、实际改动、与父代关系、观察到的效果、不能确认部分”记录。不要把源码文本差异大小直接当作语义对齐率，也不要从 objective 改善反推执行了 Plan。

将明确的单因素候选与广泛改写分开解释。若以后引入限制某个算子、拒绝超范围候选或重试生成，这会改变搜索算法和成本，必须单独版本化，不能回填到本批 A/B/C 结果。Runtime 继续验证身份、证据和预算，不自动决定科学方向。

Memory 后续问题是它是否提供近期反馈之外的知识。可增加与 Memory 长度匹配的冗余事实对照，但它属于新的预注册实验。本次真实检索、完整读取和请求引用只能证明消费，不能替代语义增益的对照。

## 最后才扩大样本并冻结最终评测

本批三 seed 的方差只作不稳定的先导估计。先确定最小有意义的目标改善、共同首轮分叉的估计对象、配对分析方式和故障处理，再据新设计下的方差确定样本量；不能直接用当前初始条件分化后的终点方差给出精确功效承诺。

主资源继续为 solver attempts，失败、中断、baseline 和 seed 重评都计数。报告生成尝试数和有效候选数，避免把记录数等同预算。外层 token 或耗时不可得时保留 unavailable，不画伪造的总成本曲线。

正式训练选择规则、样本量、停止规则和候选选择必须在最终 heldout 前冻结。只有上述前置条件满足后，才安排一次最终评测。当前诊断不据训练排名挑时机开启 heldout。
