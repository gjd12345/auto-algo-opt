# OBP 自主数学分析接入计划（M1–M3）

基线为 `main@439b991b`。外层 Coding Agent 自主选择直接探索、数学分析或其他研究方式。EoH 负责候选生成与进化，Evaluator 负责确定性评测。第一阶段交付研究工作流及记录能力。

## M1 研究上下文

在 Skill 中给出读取路径，复用 `session state`、`session read-evaluation` 和既有材料。冷启动读取 ProblemSpec、baseline、冻结训练集和指标身份。后续轮次按需读取历史候选代码、逐实例结果、执行差异与对照。保留来源引用，有现成哈希时沿用。现有行为证据提供摘要和有限事件片段，缺失的证据标记为不可用。只有在实际工作流暴露读取缺口时，才考虑新增只读入口。

交付为 Skill 的证据读取指引。无需新增聚合服务或改变冻结评测接口。

## M2 自主分析与生成接线

Agent 根据当前问题与证据决定是否分析，按需使用已有推理、知识检索与数值计算能力。可直接探索，也可放弃分析所得假设。采用分析结论时，将可执行的搜索建议写入现有 Plan 的 `direction`、`operations`、`preserve` 和 `hypothesis`。既有 Round Context 负责向 EoH 传递建议，运行证据以实际生成请求为准。分析方法、函数族和知识来源均由 Agent 选择。

交付为 Skill 中的决策指引和一个假设转化为 Plan 建议的示例。现有种子和候选生成通路继续按原合同工作。

## M3 研究决策记录

在 Plan 中增加可选的非执行元数据 `research_activity`。记录分析是否使用、研究问题、结论及其证据状态、来源引用和后续决策。缺省表示未记录，`not_used` 表示 Agent 明确选择跳过。来源引用是 Agent 的公开声明，需按原材料复查。`research_activity` 随既有 Plan 持久化和导出，EoH 只接收原有的执行建议字段。

复用现有 Plan、上下文清单、执行差异和评测事实串起记录。验收时区分建议实际送达、候选是否采纳以及评测结果。保留分析后维持原方向或放弃假设的记录。

## 交付范围

本次完成 M1–M3，以构建及针对 Plan 兼容性、持久化和提示隔离的聚焦验证为准。真实两轮 OBP 运行属于后续 M4，需分别记录接线演示和 Agent 自主选择。消融和性能归因不在本次范围内。
