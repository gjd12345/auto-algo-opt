# 在线经验内容诊断的恢复方案（待冻结）

## 研究状态

原 R/F/M 三组、三个配对种子的方案已经开始，但第一个共同首轮在 25 次真实评测后出现证据导出故障。官方收集恢复了评测事实，却不能消除任务的失败终态；运行时禁止由此继续后续轮次。已消耗的 25 次应作为本研究的实际成本保留，不能重新标成零，也不能把三个导入分支各记作 25 次新评测。详见 `research-loop-v2-memory-content-attempt-status.md`。

## 建议的预算修订

保留原定问题、三组处理、三个种子及顺序、共同首轮、每组四轮和每分支 100 次预算位置。将**本次研究累计真实 solver 评测上限由 750 次修订为 775 次**：既有中止尝试 25 次单列为基础设施成本；重新开始的完整三配对最多使用 750 次。算法质量比较只使用新完成的三配对，各组仍按相同的 100 次预算位置分析；实际总成本报告同时包含中止尝试，模型词元不可得的部分标为未知。若再出现一次无法恢复为可继续终态的技术故障，立即停止新增评测，不再自动提高上限。

这个修订只补足失败首轮所消耗的物理预算，不改变配对数或根据目标值选择种子。备选做法是在原 750 次累计上限内缩减配对数，但这会改变已冻结的研究问题和结论范围，故不推荐用于本轮。

## 重新启动前的条件

1. 在原工作区保留中止会话、原始日志、首轮事实和 R 组笔记及其哈希。新实验不得覆盖这些文件。
2. 定位导出阶段的 `PermissionError`；如需修复运行时，应在新隔离工作区完成，使旧会话仍可按旧哈希读取。至少记录具体失败位置，并对已有事实进行不产生模型请求和 solver 调用的导出、收集与继续路径验证。
3. 用修订后的运行时、实验方案哈希和 775 次**累计物理调用**上限生成新的预注册清单。新清单须分别列出已花费 25 次、完整配对可用 750 次，并禁止把失败会话导入新分支。
4. 逐个配对推进。每个共同首轮只有在任务终态允许继续、官方事实与种群快照身份一致时才能导入 R/F/M；每轮核对各组模型标识、历史材料来源、预算和成本。失败即停，不用下一组的结果填补。
5. 仍不读取 heldout；完整三对或出现可追溯且足以单列讨论的机制结果后，才修改中文学术报告。技术故障与额外成本须在方法局限中如实说明。

本文件是可供审查的修订建议，**尚未替代已冻结方案**。在修订预算明确获准并完成上述前置条件前，不启动新的模型请求或 solver 评测。
