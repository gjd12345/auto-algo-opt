## Reference 与离线门槛

- 优先用独立精确求解器生成 reference，记录版本、时限、可行上界、证明下界和最优性状态。
- 未证明最优的值只能标为 solver_reference 或合适的下界类型，不能写 known_optimum。
- 在 solver_reference 上得到 0 gap 只表示追平参考；负 gap 可能有效，不能据此认定不可能继续改善。
- 同时校准 FF、BF、精确填满后 FF、已有 G2/G4 和固定公开启发式。所有算法输入相同、预算明确，报告逐实例原始箱数和 gap。
- 检查共同 baseline 是否饱和、算法排名是否在实例间变化、实际运行成本能否承受。不要要求每个实例都难或每个经典算法都失败。
- 若共同 baseline 已达到整套主目标的可证明下界，立即停止该 profile 的质量增益实验；保留已有事实，不继续消耗剩余搜索预算。若运行已开始，按正常停止合同延伸 incumbent 曲线，并标明停止原因。仅达到未经证明的参考值不能触发“无改善空间”的判断。
- 若整套分布没有区分度，保留整批校准记录，按版本修订生成协议；不在同一版本中悄悄挑实例。

solver calls 仍是候选级尝试数。一套 36 实例和原四实例的同次数评测成本不同，应额外报告实际实例执行次数和墙钟。离线校准预算与真实算法搜索预算分开登记。

## Controller 内容门槛

先用已有 comparison packet 做不调用 EoH 的内容审查，覆盖三类问题：

1. 源码变化但行为完全相同：找出不能改变排序的系数、恒定项或分支。
2. 行为改变但 objective 不变：识别是否只是终点指标较粗，避免将其称作行为重复。
3. 实例表现相反：明确受益与退化实例对应的条件，提出能区分解释的下一步。

Reflection 的最小可审查内容：具体候选身份、观察、机制解释、尚未确认部分、下一轮可证伪预测。正确回答 unknown 好于无根据地解释。Memory 仅保存有范围的经验；判断标准是相对于现有反馈增加了什么信息。

现有脚本按轮次固定填写 Plan、hypotheses 和 Memory，不能继续作为真实外层 Agent 实验控制器。
脚本只负责传递事实、调度和验证引用；观察与下一轮决策由 Agent 阅读当轮材料后形成。
继续复用 `observations`、`hypotheses`、`next_search_advice` 与 `reflection_basis`，不另造 Reflection schema。
若现有材料不能支持某类案例，明确留空，不编造机制诊断。文本相同不是自动失败；没有候选事实支持的模板结论才是不合格。

不强制每轮切换机制，也不强制 Memory 写入。Plan 保持相同必须有可核对的理由。以证据支持为门槛，不以文本多样性为门槛。

## 分阶段实验

第一阶段：恢复 island_605 的 BP 任务身份与评测语义，审查已有 comparison packet 的 Controller 内容；随后只对恢复后的训练任务做经典算法与历史候选离线校准，零真实 EoH 请求。历史校准与新搜索分别记账，不补跑 605 次历史实验。

第二阶段：仅在经典 baseline 存在可核验改善余量、Controller 内容审查通过后，冻结恢复的训练任务、初始条件和停止规则。先以单轮转换证明“候选事实 → 具体笔记 → 下一轮 Plan → 实际请求”，再进入预注册诊断；验收运行不混入确认性样本。复用 A=facts→Plan、B=显式研究笔记→Plan、C=B+运行内 Memory 的合同，注明相对旧实验的数据与策略版本变化。A/B 材料构造相同，C 从运行内空库开始，主预算仍为每运行 100 次 solver、4 轮、每轮至多 25 次。以同预算流程总效应为主要比较。

第三阶段：需要单独估计 Plan 增益时增设 neutral 对照；A/B/C 本身不能回答这个问题。需要估计 Memory 语义增益时，再引入与 Memory 长度匹配的冗余事实对照。此项单列预注册，不自动扩充本批运行。

配对 search seed 不保证相同 provider 随机输出。严格分叉反思实验还需共同的冻结首轮种群与证据；当前 Runtime 的 run-local 引用不能手工跨 Session 冒用。在共享历史导入协议实现前，应将三 seed 结果称为配对种子的流程比较。

最后再用有信号的诊断数据估计方差与样本量。不能从本批全零质量曲线估计有效的质量收益样本量。
